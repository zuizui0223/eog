# Oikos initial-submission upload map

This map is based on the current Oikos Author Guidelines and preserves double-blind review.

## ScholarOne files

### 1. Title page file

Use: OIKOS_TITLE_PAGE_TEMPLATE_V1.md after author completion.

Must contain:
- title;
- final author order;
- affiliations;
- one corresponding author;
- corresponding-author contact details.

The corresponding author's ORCID must also be present in their ScholarOne profile.

### 2. Blinded main text

Use generated artifact:

OIKOS_BLINDED_MAIN_V1.pdf

Properties:
- no author information;
- A4, single column;
- double spaced;
- page numbers;
- continuous line numbers;
- title, abstract, keywords, Introduction, Methods, Results, Discussion, Data availability, figure captions and References.

### 3. Figures

Upload separately if desired at initial submission:

- figure_1_conceptual_outcomes_1961px.png
- figure_2_community_vs_species_1961px.png
- figure_3_exploratory_redundancy_1961px.png
- figure_4_ornl_weakest_link_1961px.png

The figures are monochrome/high-contrast and therefore do not depend on colour discrimination.

### 4. Data/code for review

Upload:

anonymous_review_data_code_v1.zip

as an additional file for review, or place the same bundle in an anonymous private-for-peer-review repository.

Do not upload a public repository URL in the blinded manuscript.

### 5. Supporting information

The current supplementary tables are generated in the paper-assets artifact:

- table_s1_site_metrics.csv
- table_s2_best_species_frequency.csv
- table_s3_response_integrity.txt

For Oikos, supporting information should be submitted separately from the main text. It is not copy-edited by the journal.

### 6. Submission-system statements

Paste/adapt:
- OIKOS_SIGNIFICANCE_STATEMENT_V1.md
- DATA_CODE_AVAILABILITY_V1.md, using a double-blind version during review
- OIKOS_DECLARATIONS_PACKET_V1.md
- AI_USE_STATEMENT_V1.md

## Do not upload in blinded files

- author names or affiliations;
- ORCID identifiers;
- personal email addresses;
- public identity-bearing repository links;
- Git history or commit-author metadata;
- API tokens or secrets.

## After acceptance

Deposit the final necessary data/code package in a permanent public repository with a persistent identifier such as a DOI. A GitHub link alone is not sufficient under NSO policy.
