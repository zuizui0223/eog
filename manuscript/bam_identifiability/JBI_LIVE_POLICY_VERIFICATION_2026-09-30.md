## Research Article format

Current live guidance supports the planned route:

- article type: Research Article;
- main text should normally not exceed 6,000 words;
- structured abstract no more than 300 words;
- required structured-abstract headings:
  Aim, Location, Taxon, Methods, Results, Main conclusions;
- title no more than 115 characters including spaces;
- running title less than 40 characters;
- 6–10 keywords, alphabetically ordered;
- up to approximately six tables/figures is normal for a Research Article;
- main sections: Introduction, Materials and Methods, Results, Discussion.

Current BAM manuscript state:

- title: 111 characters;
- running title: 30 characters;
- structured abstract: approximately 265 words;
- keywords: 8;
- main manuscript: approximately 4,500 words;
- main figures: 6.

These are within the current live limits.

## Double-anonymous review

The journal currently operates double-anonymous review.

Submission should therefore keep:

1. anonymized main manuscript;
2. separate title page / author metadata file;
3. anonymized peer-review data/code access.

The current manuscript branch contains no author names in the main review manuscript.

## Data and code at submission

Current live guidance requires underlying data and code to be available to peer
reviewers at submission.

The journal explicitly supports private-for-peer-review Dryad deposits and expects a
private review URL in submission materials. Permanent public archive/DOI information
can replace the review URL at acceptance.

For this simulation/theory paper, the review package should include at minimum:

- frozen simulation protocols;
- canonical result summaries;
- code required to reproduce the simulations and exact finite-set audits;
- figure-source CSV/JSON files;
- figure builder;
- manuscript audit scripts;
- EOG v3 code used for the implementation illustration.

## AI disclosure

Wiley general author guidance requires transparent disclosure when generative AI tools
were used to develop any portion of a manuscript. The disclosure should identify, as
applicable:

- tool/provider and version if known;
- period/date of use;
- purpose of use;
- how outputs were checked for accuracy;
- how privacy/confidentiality requirements were handled.

The exact author-approved disclosure is an administrative input and must not be
silently inferred from repository history.
